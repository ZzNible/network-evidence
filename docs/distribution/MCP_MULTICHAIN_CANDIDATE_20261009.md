## Exact available operations in this branch

- The existing **three offline tools** retain their original behavior when `NE_MCP_MULTICHAIN_ENABLED` is unset.
- **Only with** `NE_MCP_MODE=hosted` and `NE_MCP_MULTICHAIN_ENABLED=1`: expose two read-only tools: `resolve_transaction_evidence` (AFTER) and `discover_live_network_evidence` (live BEFORE/Discovery); the AFTER tool accepting exactly one Core `SubjectRef` transaction `{type:"transaction",networkId,txId}`.
- Four fixed active network identities: Base mainnet (`eip155:8453`), Base Sepolia (`eip155:84532`), Solana mainnet (`solana:5eykt4UsFv8P8NJdTREpY1vzqKqZKvdp`), Solana devnet (`solana:EtWTRABZaYq6iMfeYKouRu166VU2xqa1`). **No active zkSYS Tanenbaum profile**, no zkSYS RPC reads. Archived Tanenbaum replay is preserved in the original source suite; the already-deployed offline demo still has its explicitly historical five-profile inventory.
- No dynamic URLs or methods: pinned Base origins only, with strict chain identity, receipt, containing block and exact transaction reads. Optional OP Stack finality additionally allows only finalized/safe/latest head reads, the exact subject height, and bounded parentHash links. Pinned Solana origins allow only getGenesisHash, transaction, signature status and block. Per-method params are prevalidated, no redirects, arbitrary headers or submission.
- Source/acquisition normalization and **all network verdicts** come from unchanged `@nec/resolver-evm`, `@nec/resolver-solana` and the existing `@nec/core` wire validator. The MCP wrapper adds only bounded transport metadata, with `artifactType=network-evidence-fragment` and the exact Core artifact; **it never creates a full `NetworkEvidenceResult`** when evidence policy/preflight/context is missing.
- Shared process-local 8 successful admission slots per minute / 2 concurrent acquisitions across BOTH families; inner EVM adapter also has its own 8/min guard. Response bounds: Base 128 KB per RPC, Solana 800 KB per RPC, whole MCP AFTER envelope (including any optional adapter-local claim assessment) 450 KB; per RPC time limits Base 6 seconds, Solana 8 seconds. Public rollout also needs global quota controls when scaling past one instance, provider rate-limit confirmation, Cloud Run billing protections and adversarial review.
- Every request is a **single** source observation, not an independent cryptographic proof or network consensus. No Core confidence score. EVM inclusion/receipt ≠ OP Stack L2 finality or withdrawal finalization. Solana source-reported `finalized` ≠ cryptographic verification or x402 settlement. A pruned/null response is unavailable/insufficient evidence, not a contradiction of existence.

## Opt-in OP Stack L2 block finality (same AFTER MCP tool, NOT DEPLOYED)

- Optional request flag includeL2Finality=true is accepted ONLY for the fixed Base mainnet and Base Sepolia profiles. No extra sixth MCP tool, no new chain, no Core or resolver mutation. Default no-flag behavior is unchanged; Solana with this flag is rejected BEFORE outbound reads. The caller may also supply the existing independently assessed native protocol claim; protocol agreement, execution and L2 finality are not conflated.
- On a coherent native EVM receipt-to-block anchor, the original OP Stack resolver independently collects one RPC source identity, finalized/safe/latest heads, each required parentHash link, exact-height canonical block and a finalized-head stability re-read when the ancestry walk completed. It emits an independent, Core-validated finality-ONLY NetworkEvidenceFragment alongside the unchanged generic EVM execution/effects/dataBinding fragment. No full NetworkEvidenceResult is fabricated from two partial fragments.
- The explicit Base OP Stack family profile and native ruleset opstack.rpc-finalized-head-v1 control the evaluation; they are not guessed from numeric chain IDs. The wrapper only allows the three named block-head tags, the exact subject-block height and strict parentHash reads, all from pinned origins with bounded bytes/time. Each capture exposes method, bounded request parameters, digest/status and acquisition timestamp; raw untrusted RPC response bodies do not enter the MCP output.
- Resource ceiling: 8 ancestor hashes; at most 14 additional read-only RPC requests per opt-in beyond the generic EVM acquisition (4 reads), with an explicit counter inside the scoped fetch. Older blocks may thus get finality INSUFFICIENT even though their height lies well below the source finalized head. INSUFFICIENT means the evidence was not established under the finite ancestry budget, NOT that a transaction or its block is unfinalized. No universal N-confirmations rule.
- Exact transaction anchor unavailable: toolStatus=not_evaluated, no extra OP Stack reads. OP Stack provider read failure: toolStatus=source_unavailable, generic execution fragment preserved. Source/config/validator internal contract defects are NOT mislabeled provider outages; they fail closed as internal errors. Non-evaluated/unavailable modes cannot carry a finality fragment or captures.
- Regardless of verdict: withdrawalFinalization=not_evaluated; ethereumSettlement=not_evaluated. L2 finalized head evidence is SOURCE OBSERVATION by one RPC only, NOT independent L1 derivation, full consensus or economic irreversibility; neither withdrawal finalization nor protocol payment settlement follows.
- REAL POSITIVE, pinned 2026-10-09: Base mainnet transaction 0x71c9e27a7195bdecf1c63e73d5f959c96ddb35a27f6f1308835494c3156d625c in block 52385063. Locally hosted MCP SDK plus PUBLIC Base RPC read produced source-reported L2 finality SUPPORTED, with 6 additional native OP Stack captures. Two sanitized original read-only fixture captures under packages/mcp/test/fixtures/base-mainnet-l2-finalized-positive-{evm,opstack}.json permit deterministic full native resolver REPLAY after the live finalized head has moved.
- REAL INSUFFICIENT, pinned 2026-10-09: older Base USDC transfer 0xcf496bca417f033e3ce5ad167e82a5bf95b2d815e4493de2f4943d3058b85afb; the source finalized head was far beyond the 8-parent ancestry ceiling, yielding OP_ANCESTRY_DEPTH_EXCEEDED and INSUFFICIENT, not finality support based on block age. Future live calls for the above positive transaction may likewise become insufficient under the same bound; the pinned capture replay is stable.
